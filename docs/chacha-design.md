# 茶々入れと引用会話の実装設計

2026-11-27更新。現行仕様は最低編集文字数を持たず、5秒デバウンスと要求開始間隔30秒を使う。旧頻度プリセットは廃止した。チャット欄表示中も自動生成を許可し、ミニアイコン→本文近くの吹き出し→新規引用会話の2段階で操作する。

## 責務

| 所有者 | 役割 |
|---|---|
| `chachaSettings.ts` / `ChachaSettings` | 固定制約、人格、共通 `CHACHA_TIMING`。旧frequencyを読み込み時に無視し、新規保存は人格だけ |
| `chachaContext.ts` | CMの現在本文だけから段落・前後・見出しを抽出。合計2,000コードポイント、除外と送信範囲を制限 |
| `chachaEdits.ts` | 本文の実差分。IMEは未確定を送らず、確定前後の差分を1回通知。同一置換は候補にしない |
| `chachaTrigger.ts` | 最新候補、最終編集時刻、要求開始時刻、直近128件の重複記録 |
| `chachaSession.ts` | 文書内ランタイム、世代失効、要求・保留・吹き出しの単一タイマー、失敗と停止、生成時引用snapshot |
| `chachaEditor.ts` | CMガター、編集・抑制・可視性、文脈範囲追従、明示的な会話開始と削除 |
| `useChachaRuntime` / App | 文書と同意の寿命、設定更新、チャット・明示AI操作との抑制、引用セッションへの引き継ぎ |
| native `ai_chacha` | 保存設定revision、単一自動要求、キャンセル、無リトライ・全体60秒・応答上限 |

文書モデル、dirty、Undo、mdpkg形式に状態を追加しない。人格だけを既存settings.jsonの `chachaPreferences` に保存する。自動送信の有効化同意と、チャットの会話別接続確認は独立している。

## 編集・時間制御

実行可能時刻は `max(lastEdit + CHACHA_TIMING.idle, lastRequestStart + CHACHA_TIMING.interval)`。値は5,000msと30,000msに一元化する。追加・変更・削除・貼り付け・Undo／Redoを扱い、編集量を蓄積した閾値は持たない。要求開始の直前に開始時刻と送信文脈を記録する。

候補を個別にキューへ積まず、クールダウン中は最新だけを残す。期限到達時に同意・停止・抑制・可視性・実際の対象編集・文脈一致を再確認する。追加編集がなくても有効な候補を一度評価し、候補なしの定期送信はしない。none・エラー・キャンセルも開始済みなら間隔を守る。

重複キーは文書ランタイム内の相対ファイル、生成設定revision、実際の限定文脈JSONから作る。最大128件で、noneや失敗の文脈も記録する。設定変更だけでは候補を作らない。

抑制に入る時・解除する時と抑制中の編集では候補を破棄する。IME確定は解除後の実差分として登録する。パネルが閉じていてもチャットの物理枠が使用中なら抑制し、停止終了待ちも含める。有効化・同意・手動一時停止を勝手に変更しない。

`targetEdited` は逆変換した開始位置の変更前段落と現在の対象段落を比較する。末尾削除を見逃さず、段落全体の削除後に現れる未編集の次段落を送らない。

## 要求と状態

状態はidle、requesting、pending、collapsed、expanded。要求期限60秒、受信後の表示待ち30秒、未展開の表示180秒。expandedは時間だけでは失効しない。本文・補助文脈の編集、画面外、ファイル切替、停止などで失効する。世代とAbortSignalで遅延応答を無視し、物理要求が終了するまで次の自動要求を開始しない。認証・レート制限・連続失敗は一時停止し、自動再試行しない。

自動プロンプトは自然な感想や沈黙を許容し、固定制約が人格に優先する。限定文脈はJSONのUserとして渡し、文書中の命令を実行しない。nativeで要求を検証し、保存済み接続snapshotとキーだけを使用する。応答は8KiB、生成テキスト4KiB、256トークン。表示は既知種別・120コードポイントまでのプレーンテキスト。

## 引用会話への引き継ぎ

実際の送信User JSON、正規化済み人格、request UUID、文書インスタンス番号、相対ファイル、安全なorigin・モデル・revisionを生成時に保持する。クリック時に本文や設定から再構成しない。APIキー・絶対originパス・全ファイル・他会話は保持しない。

ガターの💬とCtrl/Cmd+Alt+Enterは本文近くのCM Tooltipを開く。コメント本文のクリックまたはEnter／Spaceで新規引用会話を作成・選択する。ランタイム・文書スコープ・有効comment IDを照合し、成功後に吹き出しを消す。重複イベントは増殖させず、上限時は残す。固定カードはテキスト表示で、補助文脈・人格を確認できる。通常相談の全文送信とは別のnative入口を使う。

引用会話の所有・通信・接続確認は[AIチャット設計](ai-chat-design.md)と[通信契約](ai-chat-transport.md)を参照。Tooltipの本文はtextContentだけで構築し、本文・selection・Undoは変更しない。会話の消去後も固定引用を残す。

## 検証

Fake Clockで5秒・30秒、none、失敗、キャンセル、最新候補、抑制解除、IMEを検証する。実CMとApp、制御可能なIPC/Channel、模擬HTTPで通信・引き継ぎ・保存分離を確認する。実測と手動確認の区別は[検証記録](chacha-verification.md)に記載する。
